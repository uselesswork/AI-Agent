## 原计划背景

让候选人画像、岗位解析和匹配报告的质量有可复核的案例与指标。编写计划时，`evals/cases.json` 只有三个虚构案例，`app/services/evaluation.py` 检查结构、字面证据与评分近似一致性；在线业务只校验部分结构规则。原三个案例通过只能说明评估器能运行，不能推断模型在真实岗位上的准确率。第十七阶段的实际结果见独立说明。

## 计划涉及的文件与职责

| 文件或目录 | 计划职责 |
| --- | --- |
| `job-agent/evals/cases.json` 或拆分后的案例文件 | 保存合成或获授权并去标识化的输入、人工期望及案例分类 |
| `job-agent/app/services/evaluation.py` | 输出各类规则检查结果，不把字面命中当作事实真实性证明 |
| `job-agent/scripts/evaluate_outputs.py` | 运行离线回归；显式选择服务商时运行真实模型评估并汇总指标 |
| `job-agent/tests/test_evaluation.py` | 验证评估器能识别错误证据、遗漏要求、评分不一致等反例 |

## 案例与指标计划

1. 首批扩展到至少 20 个经人工核对的案例，覆盖不同简历格式、空缺字段、模糊技能、岗位硬性条件、实习时间要求、证据冲突和无法确认的情况。案例分组，避免同一模板改写充数。
2. 为每例写明可检查的期望：必要字段、不得编造的内容、原文证据位置、关键岗位要求及可接受的评分范围。开放式建议另设人工评分准则，不强行用字面匹配替代语义判断。
3. 汇总结构通过率、证据引用命中率、硬性条件漏判数和评分一致性；真实模型运行时另记录模型标识、耗时与估算成本。对失败案例保留分类和复核结论。
4. 离线评估保持默认、可重复且不调用外部服务。真实模型评估须显式启用，使用可公开的虚构案例；不将真实个人简历或 API Key 提交仓库。

## 完成标准与验证范围

- 案例有来源/构造说明、人工审核人或审核记录、预期结果及分类；能够复跑并比较修改前后的结果。
- 正反例测试验证评估器本身不会把明显错误输出判为通过。
- 报告分别标注离线预置输出、真实模型输出和人工复核范围；不把虚构案例通过率解释为真实用户场景准确率。
- 若后续替换模型或提示词，可用相同案例集对比结果，并记录新失败项。

## 限制与依赖

模型输出具有波动性，分数和文字表达不宜要求完全相同；事实真实性仍需要人工核验。扩充案例前先确定隐私处理和人工审核流程。参考现有[第十四阶段评估边界](第十四阶段-评估端到端测试与部署监控.md)。
