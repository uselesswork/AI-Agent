# 第十三阶段：账号登录、数据隔离与个人数据管理

## 一眼看懂本阶段

本阶段为原本无登录的本地求职助手增加本机账号、服务端登录会话和按账号隔离的数据访问。`/upload` 先显示登录界面，登录后才加载投递、资料库、来源记录及提醒；页头可导出当前账号数据、退出，或经密码复核后永久删除账号及其数据。这里没有公开注册入口，也不支持将服务直接发布到公网。

旧 MySQL 数据不会自动归属于任意网页访客，应用访问 MySQL 时也不自动创建账号表。管理员须在停止应用写入、备份数据库后，于本机交互式运行初始账号升级脚本；脚本把既有简历、岗位、报告、投递和公开岗位来源认领到唯一初始账号。密码仅在终端输入且不回显，不写入本项目文档或脚本参数。新增其他账号使用另一条本机命令，从空资料库开始。

## 文件与职责

| 文件 | 本阶段职责 |
| --- | --- |
| `app/core/database_schema.py` | 声明 `users`、`auth_sessions`、`user_assets`，为 `job_imports` 增加账号归属及按账号来源唯一约束；原有十一张业务表仍保留 |

| `app/services/ownership.py` | 顶层数据归属查询、写入和账号专属去重键 |
| `app/services/personal_data.py` | 当前账号业务数据的 JSON 导出与单事务删除 |
| `app/main.py` | 对全部 `/api/` 路由统一要求登录；仅登录和账号配置状态为公开 API |
| `app/services/application_relations.py`、`application_repository.py` | 归属新的简历/岗位/报告/投递，隔离看板、原文与事件 |
| `app/services/library_repository.py`、`discovery_repository.py` | 资料库与公开岗位来源按账号读写；相同画像或来源在不同账号间不共用 |
| `app/services/draft_version_repository.py`、`annotation_repository.py`、`planning_repository.py` | 草稿、人工标注、日程和提醒通过所属投递限制访问 |

## 数据流和隔离原则

登录时用 `scrypt` 验证慢哈希，生成随机会话令牌和 CSRF 令牌。浏览器只收到 `HttpOnly`、`SameSite=Strict` 会话 Cookie；数据库只保存会话令牌的 SHA-256 摘要。会话有效期 12 小时，退出时服务端撤销；非本地 HTTP 地址设置 `Secure` Cookie。本地 `127.0.0.1`/`localhost` HTTP 因开发环境需要不设置 `Secure`，不能作为公网部署配置。写请求必须携带 `X-CSRF-Token`；带 `Origin` 或 `Referer` 时还要同源。响应标记 `Cache-Control: no-store`。

身份在 API 中间件完成解析，再绑定到请求上下文。`resumes`、`jobs`、`match_reports`、`applications` 四类顶层资料由 `user_assets` 记录所属账号；子表通过投递或岗位关系限定。`job_imports` 直接记录 `user_id`，按账号、来源、招聘板、外部职位 ID 去重。新画像和岗位使用含账号标识的去重键，避免不同账号复用同一数据库行。对其他账号的对象，详情、更新和删除按不存在处理；列表仅包含本账号资料。上传后的简历文件字节仍不落库；未明确同意留存原文的请求仍不保存原文。

`GET /api/auth/export` 导出当前账号的十一张业务表关联记录，包含可能敏感的简历原文和备注，但**不包含**密码哈希、会话、CSRF 令牌、API Key 或 `.env`。导出为 JSON；它不是自动可恢复的导入备份。`POST /api/auth/delete` 需要当前密码及显式确认，按外键依赖次序在单个数据库事务中删除本账号业务行、归属记录、会话和账号；不删除其他账号的数据，也不清理数据库备份、用户已下载的文件或第三方模型服务商曾处理的信息。

## MySQL 升级和首次使用

先备份当前 MySQL 数据库，关闭运行中的应用及其他写入程序，再在 `D:\Agent\job-agent` 执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.upgrade_user_access
```

终端会要求输入初始用户名、密码和确认密码。脚本创建缺失的账号表，为旧 `job_imports` 加 `user_id`，认领历史数据，改为按账号的来源唯一约束。MySQL DDL 不能整体回滚；失败后应先查看数据库状态和备份，再用同一初始账号凭据重试。不要在其他账号已有数据后重跑“认领全部旧数据”。现有 MySQL 已由用户在本机执行成功；其他未升级库才需要运行此命令。完成后重启后端并登录 `/upload`。继续创建空账号时运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.create_user
```

账号启用之后，旧的 `scripts.init_database` 和 `scripts.seed_applications` 不再可用于追加样例；两者会拒绝向多账号库写入。请在网页中以当前账号建立自己的测试资料。`create_user` 仅适合能访问本机数据库配置的管理员，不应给不可信的远程用户执行。

## 接口和页面

| 接口 | 作用 |
| --- | --- |
| `GET /api/auth/status` | 公开检查是否已有账号，不返回账号列表 |
| `POST /api/auth/login` | 用户名、密码登录并建立 Cookie 会话；返回当前用户名和 CSRF 令牌 |
| `GET /api/auth/me` | 读取当前账号及本会话 CSRF 令牌 |
| `POST /api/auth/logout` | 撤销当前会话 |
| `GET /api/auth/export` | 下载当前账号业务数据 JSON |
| `POST /api/auth/delete` | 密码复核后删除当前账号和数据，`confirmed` 必须为 `true` |

原有 `/api/resumes`、`/api/jobs`、`/api/matches`、`/api/applications`、`/api/library`、`/api/discovery`、`/api/planning` 均须登录；有写操作的调用还需 CSRF 令牌。`/upload` 的静态页面和 `/docs` 可公开访问，但它们不能读取未授权的业务接口。Swagger 中手工调试时，浏览器须已登录，写请求还需填写从 `GET /api/auth/me` 获得的 `X-CSRF-Token`；不要把真实令牌复制到文档或截图。

## 验证与限制

本阶段的自动化测试使用临时 SQLite 和本地 TestClient，覆盖未登录拒绝、错误密码、Cookie 属性、CSRF 与跨来源写入拒绝、登出失效、跨账号看板/草稿/日程/资料库隔离、相同公开来源按账号独立保存、个人导出与删除不影响另一账号，以及升级脚本拒绝 SQLite。旧阶段回归测试使用测试专属模拟身份，不能视为真实登录联调。现有 MySQL 已执行初始账号升级；**没有**在真实库验证账号密码登录、登录后业务读取、数据导出或删除，也没有真实模型调用、浏览器端到端或公网安全测试。

2026-10-28 升级前只读复核：三个账号相关表已存在但均为空，`job_imports` 仍无 `user_id` 且保留旧唯一约束；现有 7 条投递的三个关联 ID 均非空。用户随后在本机交互式运行升级脚本，报告认领简历 2、岗位 7、报告 7、投递 7 条。升级后只读复核：`users` 1 行、`user_assets` 23 行，四类归属数与业务表数量一致；`job_imports.user_id` 为非空列，唯一约束已改为包含账号 ID。只读 API 检查确认已配置状态为 200、未登录读取投递为 401、页面为 200。未读取或使用用户输入的密码，故无法声称真实账号登录及登录后操作已通过。

当前没有公开注册、密码重置、登录限流、审计日志、权限角色、加密数据库备份或自动清理过期会话。建议仅在可信本机网络使用；若未来需要公网部署，应先补齐 HTTPS、反向代理来源策略、登录限流、备份治理及安全测试。安全设计参考：[OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[CSRF 防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。
