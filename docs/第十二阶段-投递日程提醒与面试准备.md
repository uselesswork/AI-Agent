# 第十二阶段：投递日程、站内提醒与面试准备

核对日期：2026-10-27。

## 一眼看懂

在 `/upload` 求职看板的每条投递中，可新增、修改、完成、重新打开或删除三类日程：投递截止、面试安排、跟进事项。网页顶部汇总所有未完成且已经逾期或未来 7 天内到期的事项。这里的“提醒”是**打开或刷新网页时读取的站内提示**，没有后台调度、邮件、系统推送，也不会自动联系招聘方。

对已人工确认的草稿版本，可生成面试准备提纲。后端只读取该版本的简历正文、已保存岗位要求和匹配报告中的差距，列出练习问题与可复习的已确认材料行；找不到直接材料时明确提示准备真实案例，不生成候选人的答案，不再调用大模型。确认版本也不意味着系统核实了事实。

## 数据流和规则

1. 用户在“我的求职看板”选择某条投递的“管理日程”，填写事项类型、标题、本地日期时间及可选备注。网页用浏览器所在时区解释 `datetime-local`，提交带时区的 UTC ISO 时间；后端拒绝没有时区的时间。数据库以 UTC `DATETIME` 保存，读取时标记为 UTC，再由网页按本地时区展示。更换电脑时应核对系统时区。
2. 每条投递可以有多条日程，包括多次面试或跟进；当前没有强制“每个投递只能有一个截止日期”。修改标题、时间、备注不会改事项类型，也不会自动改变看板投递状态。标记完成时记录完成时间，重复标记完成不改首次时间；重新设为未完成会清空完成时间。删除投递时日程按外键级联删除。
3. `GET /api/planning/reminders?days=7` 实时读取未完成且在未来 7 天内到期或已经逾期的事项，按时间升序返回最多 100 条；超过时返回 `truncated=true`。`days` 可为 0～30。已完成和更远的事项仍在投递日程中，但不进入本次提醒。页面初次加载、点击“刷新提醒”或“刷新记录”、日程变更后读取；关闭网页不会主动提醒。
4. 面试准备仅对指定投递的已确认版本开放。提纲优先按岗位必备技能生成问题；如果没有必备技能则使用岗位职责，另列最多两项旧匹配报告差距。每个技能只查找已确认简历中直接包含该关键词的行作为“材料线索”；找不到时标记 `needs_example=true`。匹配报告可能来自模型，它的差距判断应人工核对。提纲不保存为新表、不修改草稿版本、不发送材料给模型或招聘方。

## 接口

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/planning/reminders?days=7` | 近期/逾期未完成事项，最多 100 条和截断标记。 |
| `POST /api/planning/applications/{id}/milestones` | 创建投递截止、面试或跟进事项；请求含 `kind`、`title`、带时区 `scheduled_at`、可选 `notes`。不存在的投递 404，输入无效 422。 |
| `GET /api/planning/applications/{id}/milestones` | 列出该投递全部日程及 `overdue`、`soon`、`later`、`completed` 状态。 |
| `PATCH /api/planning/applications/{id}/milestones/{milestone_id}` | 修改标题、时间、备注或 `completed` 布尔值；不更改类型。跨投递或不存在返回 404。 |
| `DELETE /api/planning/applications/{id}/milestones/{milestone_id}` | 删除指定事项，成功 204。 |
| `GET /api/planning/applications/{id}/interview-prep?version=1` | 基于已确认版本返回问题、材料线索与清单；未确认 409，版本不存在 404。响应 `Cache-Control: no-store`。 |

## MySQL 增量升级

第十二阶段增加第十一张表 `application_milestones`：主键 `id`，`application_id` 外键指向 `applications.id` 并在删除投递时级联，`scheduled_at` 有索引。旧十表不加列、不回填未知截止日期。已有库先备份并暂停应用写入，在 `D:\Agent\job-agent` 执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.upgrade_application_milestones
```

脚本只建缺失表并回读数量，不自动生成日程或发送提醒。完整字段说明见[数据库设计与字段说明](数据库设计与字段说明.md)。

## 验证与边界

- 2026-10-27 完整自动化测试 70 项通过，Ruff、前端 JavaScript 语法、差异空白及本地 Markdown 链接检查通过。新增测试使用临时 SQLite 和人工夹具，验证时区拒绝、日程增删改查、跨投递隔离、完成时间幂等、逾期/未来提醒、投递删除级联及已确认版本的准备门槛。没有真实模型调用或浏览器端到端自动化测试。
- 真实 MySQL 日程表曾在修复测试隔离前被应用自动建表逻辑创建，并误写 9 条虚构测试日程；已按明确的 ID、内容与创建时间核对并精确删除，最终表内 0 条。独立升级脚本随后幂等执行成功；只读检查确认九列和指向 `applications` 的外键，提醒及单条投递日程列表只读接口均返回 200。没有保留测试日程，也没有对真实投递本身做修改。后续测试已修正为临时 SQLite 仓储。
- 尚无后台调度、桌面/邮件通知、日历同步、时区偏好设置或自动确定招聘截止日期。日程及会议备注完全由用户输入，可能过期或包含敏感会议链接。
- 面试提纲是练习提示，不是模型生成的标准答案、事实核验或面试通过预测；它不会自动把报告中的差距当成真实缺点。当前仍是无登录的本地单用户工具，不应直接暴露公网。
