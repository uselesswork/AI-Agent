# 第十一阶段：材料模板与人工证据标注

核对日期：2026-10-27。

## 一眼看懂

看板“生成定制材料”现在可选择“标准模板”或“精简模板”。两者只重新组织已保存的结构化画像，不调用大模型；默认标准模板保持旧接口兼容。精简模板只显示相关度靠前的部分技能和项目，省略并不代表原画像没有这些事实。自动预览和自动 DOCX/PDF 下载使用同一模板参数。

对于用户此前明确同意留存简历/JD 原文的投递，已保存草稿版本的证据报告现在逐行提示未命中，以及“简历行只在岗位原文命中”的重点风险。用户可以为某行手动选择简历或岗位来源，粘贴该来源中确实存在的原文片段，并写核对备注。关联只是人工提供的线索；既不把岗位要求变成个人经历，也不代表系统验证了整行事实。删除留存原文时，关联标注也会删除。

## 数据流与规则

1. 在看板卡片选择模板后点击“生成定制材料”。`GET /api/applications/{id}/draft?template=standard|compact` 返回两份草稿；旧客户端省略参数时仍为 `standard`。自动下载接口也可带相同参数。模板不新增模型提示词或费用。
2. 用户编辑后保存为不可覆盖的新草稿版本。`draft_versions` 仍只保存两份文档 JSON，不额外记录模板名；版本内容以实际保存的文档为准。载入旧版再保存会创建新版本。人工确认与下载门槛沿用第六阶段。
3. 有留存原文的版本可调用证据报告。报告先做第七阶段的完整行字面匹配，再标记未命中行，以及简历行仅在岗位原文命中的情况。命中也仅是字面结果；“高风险”提示不自动阻止人工确认或下载。
4. 在“证据与人工标注”里对某行选择简历或岗位原文，粘贴原文片段并可写备注。后端检查该片段去空白、忽略英文大小写后至少 8 个有效字符，且确实存在于所选投递的对应留存文本；同时检查章节和行序号属于指定不可变草稿版本。每个版本的每一行最多一条标注，重复保存更新该标注，不改变草稿正文。
5. 标注以版本 ID、投递 ID、文档、章节序号和行序号定位，不能跨投递借用原文。删除留存原文时同时删除标注；删除投递时由外键级联清理。即使标注片段存在于原文，也不证明整行推断或量化成果正确，因此未命中的风险提示不会因为人工关联而消失。

## 接口

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/applications/{id}/draft?template=standard|compact` | 预览指定模板，默认 `standard`；未知模板 422。 |
| `GET /api/applications/{id}/draft/{resume|letter}.{docx|pdf}?template=...` | 按同一模板生成自动建议稿文件。 |
| `GET /api/applications/{id}/draft-versions/{version}/evidence` | 原接口增强：返回章节/行序号、注意级别及原因、人工标注和岗位文本误作简历事实的计数。无留存原文仍为 409。 |
| `PUT /api/applications/{id}/draft-versions/{version}/annotations` | 保存或更新一行关联；请求含 `document`、零起始的 `section_index`/`line_index`、`source_kind`、`source_quote`、可选 `note`。片段不在所选原文或行位置错误返回 422；未留存原文返回 409；版本不存在返回 404。 |
| `DELETE /api/applications/{id}/draft-versions/{version}/annotations?document=resume&section_index=0&line_index=0` | 删除指定行的关联；重复删除返回 204。 |

## MySQL 增量升级

新增第十张表 `draft_annotations`。`version_id` 指向 `draft_versions.id`，`application_id` 指向 `application_sources.application_id`，均为级联删除；`(version_id, document, section_index, line_index)` 唯一。已有九表库先备份、暂停应用写入，再于 `D:\Agent\job-agent` 执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.upgrade_draft_annotations
```

脚本只建缺失表并回读数量，不读取或复制原文、不写标注。完成后重启后端。MySQL DDL 隐式提交，不可视为整批可回滚事务。完整字段见[数据库设计与字段说明](数据库设计与字段说明.md)。

## 验证范围与限制

- 2026-10-27 完整自动化测试 65 项通过，Ruff、前端 JavaScript 语法和差异空白检查通过。新增测试使用临时 SQLite 和人工测试文本，不调用真实模型；模板输出、来源片段校验、投递/版本隔离、风险提示、撤回原文或删除投递后的标注清理均有覆盖，升级脚本拒绝 SQLite。
- 真实 MySQL 已用独立脚本增建空的 `draft_annotations`（0 条）；只读检查确认十一列、行定位唯一约束、两个外键。真实库的投递列表和精简草稿只读接口均返回 200；没有向真实库写入标注或原文，也未进行浏览器端到端测试。
- 没有语义级事实核验、自动识别夸大/造假、逐字核验模型报告、任意附件证据上传或审批工作流。风险提示只基于字面匹配及文档类型，可能误报和漏报。
- 人工标注目前只支持已授权留存的简历/JD 文本；旧投递不能静默补原文。标注中引用的片段与备注可能含个人信息，项目仍是无登录的本地单用户工具，不应直接暴露公网。
- 已确认版本的关联仍可更新，但不会修改版本正文或原有 `reviewed_at`；确认只记录用户操作，不等于标注获系统认可。模板名本身不写入版本表，历史版本只能以保存的内容为准。
