## 一眼看懂

第五阶段的自动草稿现在可以在求职看板中逐章节编辑。保存时创建不可覆盖的新版本；用户核对后明确确认某个版本，才能下载该版本的 DOCX/PDF。历史版本可重新载入编辑区作为下一版的起点。自动生成稿仍可按第五阶段接口下载，但它不是“已人工核对版本”。

本阶段不调用 OpenAI 或 DeepSeek，不会自动判断用户填写的事实是否真实，也不会自动发送求职材料。确认动作只记录用户已核对的操作，不能代替与原始简历、岗位要求逐项比对。

## 数据流

1. 看板点击“生成定制材料”，仍调用第五阶段接口，显示自动草稿与修改建议。
2. 编辑器以自动草稿为起点；用户可修改标题、章节标题和逐行正文，也可添加或删除章节。生成内容与编辑框中的未保存修改只存在于当前页面。
3. 点击“保存为新版本”时，前端提交两份文档。后端在数据库事务中锁定所属投递记录，分配该投递的下一个版本号，再把两份文档的完整 JSON 写入 `draft_versions`。旧版本内容不更新。
4. 历史列表按版本号倒序展示；“载入编辑”会取回该版本并放入编辑器，保存后仍创建新版本。
5. 未核对版本的下载接口返回 409。用户对照原件确认后，后端记录 `reviewed_at`；此后该版本的简历/求职信可分别导出 DOCX/PDF。重复确认不会改写首次确认时间。
6. 删除投递记录时，数据库外键 `ON DELETE CASCADE` 删除其版本；独立画像、岗位和匹配报告仍遵循第四阶段的保留规则。

版本表不保存原始简历或岗位全文。`reviewed_at` 不是事实校验结果，也不是投递时间。当前单用户本地应用没有身份认证；不要把含个人信息的接口直接暴露到公网。

## 新接口

| 方法与路径 | 作用 |
| --- | --- |
| `POST /api/applications/{id}/draft-versions` | 提交 `resume`、`cover_letter` 两份文档，创建待核对版本，返回详情。 |
| `GET /api/applications/{id}/draft-versions` | 按版本号倒序列出摘要、创建时间和核对时间。 |
| `GET /api/applications/{id}/draft-versions/{version}` | 读取指定版本的两份完整文档。 |
| `PATCH /api/applications/{id}/draft-versions/{version}/review` | 请求体 `{"confirmed": true}`，记录人工核对确认。 |
| `GET /api/applications/{id}/draft-versions/{version}/{resume\|letter}.{docx\|pdf}` | 仅对已确认版本下载文件。 |

记录或版本不存在返回 404；请求结构/内容不符返回 422；未确认导出返回 409；PDF 缺少中文字体时返回 503。每份文档须有 1～30 个章节，标题不超过 200 字符，每章节不超过 100 行、单行不超过 3000 字符，两份材料合计不超过 100000 字符。服务端只校验结构和容量，不校验人工编辑内容的真实性。

第五阶段的 `GET /api/applications/{id}/draft` 和自动草稿下载接口保持不变，不会隐式读取或覆盖历史版本。只有带 `/draft-versions/{version}/` 的下载地址返回指定人工版本。

## MySQL 升级与运行

已有第四/第五阶段 MySQL 库先备份，再在 `D:\Agent\job-agent` 下执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.upgrade_draft_versions
```

脚本检查原 `applications` 表存在，再增量创建 `draft_versions`；可重复执行，不修改原有五张表，也不会额外导入六条虚构测试记录。应用仓储初始化同样会创建缺失表，但显式运行脚本便于在重启前确认结构。新库仍可使用 `scripts.init_database` 完整初始化；该命令会执行旧数据关联回填和测试数据导入，作用范围不同。

升级后重启后端，访问 `http://127.0.0.1:8000/upload` 的“我的求职看板”，在一条投递记录内完成生成、编辑、保存、载入、确认、下载。

## 验证范围与限制

2026-10-22：完整自动化测试 46 项通过，Ruff 与前端 JavaScript 语法检查通过。新增版本测试使用临时 SQLite 和人工夹具，覆盖接口、编辑内容导出、不可覆盖的历史版本、确认门槛及删除级联；不调用真实大模型，也不等同于真实 MySQL 并发或真实简历事实核查。

真实 MySQL 已执行独立增量脚本，新表 `draft_versions` 创建成功且为空；原五表计数仍为 1/6/6/6/6。只读结构检查确认七个字段、指向 `applications` 的 `CASCADE` 外键及 `(application_id, version)` 唯一约束。FastAPI TestClient 连接真实 MySQL 读取投递列表 200（六条）、版本列表 200（零条）。未对真实 MySQL 执行版本创建、核对、导出或删除，也未进行浏览器操作测试。

- 历史版本不可原地修改；若需修正，载入后保存新版本。已确认版本也保留原样。
- 第六阶段交付时没有版本差异对比；第七阶段已增加文本差异接口与看板展示。草稿回滚按钮、确认撤销、多人协作和用户权限隔离仍未实现。
- 用户可以自行写入未经证实的内容；系统不会因勾选确认就证明其真实。
- 第五阶段 DOCX 页面级目视核查缺少 LibreOffice 的环境限制仍在；本阶段沿用相同导出器。
