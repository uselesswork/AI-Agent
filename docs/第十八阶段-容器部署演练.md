# 第十八阶段：容器部署演练

> 核对日期：2026-11-18。Windows 11 专业版本机已完成隔离 MySQL 容器的构建、启动、登录、投递持久化、应用重启及清理演练。
> [返回项目说明](../README.md) · [第十四阶段容器配置](第十四阶段-评估端到端测试与部署监控.md) · [原待办计划](待办-容器部署演练.md)

## 一眼看懂本阶段

新增可复跑的隔离演练入口。它生成临时随机密码，在 Docker Compose 专属项目中启动 MySQL 8.4，用第十六阶段 Alembic 迁移建表，再创建虚构账号并启动应用。脚本通过 HTTP 检查健康、就绪、页面、静态资源、登录、投递写入和读取；停止并重启应用容器后，再次读取同一投递。最后检查应用日志并删除本次演练容器与数据卷。它不会使用日常 `job_agent` 库或真实模型。

## 文件与职责

| 文件 | 职责 |
| --- | --- |
| `job-agent/Dockerfile`、`.dockerignore` | 镜像纳入 Alembic 配置与迁移脚本，继续排除 `.env`、测试和缓存；运行身份为非 root `jobagent` |
| `job-agent/compose.exercise.yaml` | 独立 MySQL 8.4 与应用服务，MySQL 使用专属数据卷，应用仅绑定本机 `127.0.0.1:18080`、只读根文件系统与 `/ready` 健康探针 |
| `job-agent/scripts/container_exercise.py` | 生成临时凭据、执行构建和迁移、发起虚构业务请求、检查重启持久化与日志、结束时清理专属项目 |
| `job-agent/.env.docker.example` | 常规容器部署占位示例的 OpenAI 模型名同步为 `gpt-6-luna`；演练不读取该文件或真实 Key |
| `job-agent/compose.yaml` | 常规本机部署配置仍使用独立 `.env.docker`，不自动创建数据库或账号 |

## 数据流与复跑步骤

在 Windows 11、Docker Engine 29.7.2、Docker Compose v5.5.0 上，于 `D:\Agent\job-agent` 运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.container_exercise
```

Docker 需能取得 `python:3.12-slim` 和 `mysql:8.4`。本机首次从 Docker Hub 拉取 Python 基础镜像时，认证端点连接超时；改从公开 ECR 镜像源拉取同版镜像并赋予本地标签后，原 `Dockerfile` 构建成功。遇到同类网络问题可先运行：

```powershell
docker pull public.ecr.aws/docker/library/python:3.12-slim
docker tag public.ecr.aws/docker/library/python:3.12-slim python:3.12-slim
```

脚本调用 Compose 构建应用镜像，启动隔离 MySQL，并运行 `scripts.manage_migrations initialize` 到 `0002_user_assets_owner_index`。仅初始化容器接收临时虚构账号密码；应用运行容器只接收本次隔离库连接。HTTP 会话使用 Cookie 与 CSRF 令牌创建一条虚构投递，重启后再次读取。脚本的 `finally` 清理自身随机命名的 Compose 项目和数据卷；**这些演练数据会在结束时删除**。端口 `18080` 须空闲。常规 `compose.yaml` 的 `.env.docker` 与日常数据库均不参与。

## 实际结果与边界

- 本机最终一轮构建耗时约 43.0 秒，镜像大小 103.6 MB；镜像为 Linux amd64，运行用户 `jobagent`。
- `/health`、`/ready`、`/upload`、`/static/app.js` 均返回 200。虚构账号登录、投递写入与读取成功；停止并重启应用容器后，原会话仍能读取同一 MySQL 投递。
- 应用日志中未出现测试密码、会话 Cookie 值、查询标记或虚构简历文件名。演练项目的容器与数据卷清理退出码为 0，随后只读确认无残留。
- Docker 配置静态测试 2 项通过，Ruff 检查通过；本轮未重跑全量普通测试，核心容器路径由上述实际演练验证。
- 第一次演练的 HTTP 探测脚本有 `urllib` 调用错误，已经修正并完整重跑成功；它没有触及日常数据库，失败轮次的容器与数据卷也已清理。
- 验证使用一台已有 Docker 的本机，不等于在第二台干净开发机或公网环境验证。没有调用真实模型、处理真实简历、测试 PDF 导出、演练数据库备份恢复或验证 HTTPS、限流与密钥管理。容器重启持久化依赖 MySQL 数据卷；执行 `down -v` 会删除本次演练数据。
