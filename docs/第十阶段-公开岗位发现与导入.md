# 第十阶段：公开岗位发现与导入

核对日期：2026-10-27。

## 目标与实际成果

在 `/upload` 页面增加“选择招聘板并发现岗位”区：用户明确选择 Greenhouse 或 Lever，输入该公司的 Board / Site 标识后，读取该招聘板的公开岗位，按关键词、地点与实习标记筛选，查看预览并逐条确认导入。预览不写数据库；导入时才使用 OpenAI 或 DeepSeek 将岗位描述结构化，保存到第九阶段岗位资料库，同时留下来源记录。相同来源岗位再次导入会复用原记录，不重复调用模型。

支持的来源以官方公开接口为依据：[Greenhouse Job Board API](https://docs.greenhouse.io/job-board.html)、[Lever Postings API](https://github.com/lever/postings-api)。这里只读取公开职位 GET 接口，不调用两家平台的申请提交接口；本项目没有一键投递或自动发送功能。

## 数据流与去重规则

1. `POST /api/discovery/search` 先校验来源及 Board / Site 标识。标识只允许英文字母、数字、下划线、连字符；服务器根据来源拼出固定的 Greenhouse 或 Lever API 地址，**不接受客户端提供的任意抓取 URL**。读取公开 JSON 后标准化岗位标题、地点、岗位类型、链接和描述，应用筛选条件，返回最多 100 条预览及已导入标记。公开接口不提供公司名时保持空值，页面仅将 Board / Site 标识用于识别来源，不伪造公司信息。查询本身不落库，也不调用大模型。
2. Greenhouse 一次读取指定招聘板的职位列表并请求公开描述；Lever 最多读取前三页、每页 100 条。单次响应限制 4 MB、超时 10 秒，不跟随重定向。达到来源或展示上限时页面提示结果可能不完整；这不是对整个平台或全部公司的搜索。
3. “只看实习”是标题或岗位类型包含“Intern / 实习 / Co-op”等字样的保守字符串筛选，可能漏掉没有这些词的实习岗位，也可能误收其他岗位。关键词在标题和描述中匹配；地点按来源给出的地点字符串匹配。筛选不能代替阅读原招聘页。
4. 点击一条预览的“解析并导入资料库”后，网页先征求确认。后端优先查 `job_imports` 唯一来源身份（来源 + 招聘板 + 外部职位 ID）；若已导入，直接返回旧记录，不再次请求模型。否则重新读取该职位详情，使用所选模型解析描述，复用第九阶段的规范化岗位链接/画像去重逻辑，再写 `job_imports`。因此新来源可指向资料库中已有岗位，但不会覆盖旧岗位画像或旧投递。
5. 来源记录保存 `job_id`、来源、招聘板标识、外部职位 ID、招聘页链接和导入时间。原始外部 API 响应和完整 JD 正文不写入来源表或共享 `jobs.raw_description`。网页提供最近 100 条来源记录及原招聘页链接。

## 新接口

| 接口 | 说明 |
| --- | --- |
| `POST /api/discovery/search` | 请求 `source`（`greenhouse` 或 `lever`）、`board_token`、可选 `keyword`、`location`、`internship_only`；返回 `items`、`scanned`、`truncated`。未知招聘板 404，来源故障 502，参数无效 422。 |
| `GET /api/discovery/imports` | 返回最近 100 条已导入来源记录。 |
| `POST /api/discovery/imports` | 请求 `source`、`board_token`、`external_id`、可选 `llm_provider`；成功返回来源记录、是否新导入、是否复用已有岗位。岗位消失 404，描述过短 422，模型配置缺失 503，模型服务失败 502。 |

## MySQL 增量升级

第十阶段只新增 `job_imports`，通过 `(source, board_token, external_id)` 唯一约束避免同一公开职位重复建立来源记录；`job_id` 外键指向 `jobs.id`，删除无其他引用的岗位时来源记录级联删除。旧八表不加列、不回填。已有 MySQL 库建议先备份、暂停应用写入，再在 `D:\Agent\job-agent` 执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.upgrade_job_imports
```

脚本只建缺失表并回读数量，不抓取岗位、不导入测试数据。完成后重启后端。MySQL DDL 隐式提交，不可视为整批可回滚事务。

## 验证范围和未实现功能

- 2026-10-27 完整自动化测试 60 项通过，Ruff、前端 JavaScript 语法和差异空白检查通过。新增测试使用临时 SQLite、模拟的 Greenhouse/Lever JSON 和模拟岗位解析器，验证来源校验、筛选、导入和重复跳过模型；不会联系真实招聘板或真实大模型。
- 真实 MySQL 已用独立脚本增建空的 `job_imports`（0 条）；只读检查确认七个字段、来源三元组唯一约束、一个外键及来源列表读取。没有向真实库导入岗位、联系真实招聘板、调用真实模型或执行浏览器端到端操作。不能将模拟测试称为真实来源/模型联调。
- 没有跨所有招聘网站的全网搜索、定时抓取、订阅监控、任意网页爬虫、职位下架同步或自动投递。Board / Site 标识需要用户从目标公司的招聘页确认，项目不会猜测它。
- 外部职位可能变化或关闭。预览是当次公开接口结果；导入时会重新获取详情。已导入来源不会自动刷新或重新解析，即使职位后续变化也保留当时的结构化岗位画像。
- 导入时岗位描述会发送给所选模型服务商，可能产生费用；公开接口返回的职位内容不保证真实、完整或仍在招聘。匹配前应打开原招聘页核对。
- 当前单用户本地项目无登录和用户隔离，不应把带有个人资料的其他接口直接暴露公网。岗位发现请求不向招聘板发送简历画像。
