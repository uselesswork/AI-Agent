## 2. 具体完成的工作

### 2.1 统一模型调用

`OpenAICompatibleClient` 提供统一的异步 `generate_json()` 方法；`JSONGenerator` 协议约定 `provider`、`model` 和 JSON 生成能力，使业务服务可以依赖同一接口，也方便测试替换成模拟生成器。

当前客户端使用 Chat Completions：

| 参数 | OpenAI 分支 | DeepSeek 分支 |
| --- | --- | --- |
| JSON 模式 | `response_format={"type":"json_object"}` | 同左 |
| 输出上限 | `max_completion_tokens` | `max_tokens` |
| 附加选项 | 无该项 | `thinking.type` 设置为 `disabled` |
| 地址、密钥、模型 | `OPENAI_*` | `DEEPSEEK_*` |

返回后清理可能存在的 Markdown 代码块，解析 JSON，检查顶层必须为对象。超时、API 错误、空内容、无效 JSON 分别转成应用异常。

以上是项目当前实现，不能据此推断其他兼容服务或所有模型支持相同参数。

### 2.2 配置与服务商选择

- `Settings` 从项目 `.env` 读取 UTF-8 配置。
- `ProviderConfig` 将选定服务商的参数整理为统一对象。
- `provider_config(provider)` 优先使用请求参数，省略时使用 `LLM_PROVIDER`。
- 密钥使用 `SecretStr`；客户端内部才提取实际值。
- 校验密钥、非空模型名、正数超时、非负重试次数和正数输出上限。
- 前端增加单选卡片，将 `provider` 随分析表单提交。

页面切换服务商无需重启；修改 `.env` 后需要重启，因为 `get_settings()` 使用缓存。

### 2.3 结构化候选人画像

`StrictModel` 设置 `extra="forbid"`，拒绝未声明字段。

| 模型 | 主要信息 |
| --- | --- |
| `Evidence` | 原文引用 `quote` 和来源章节 `source_section` |
| `BasicInfo` | 姓名、邮箱、电话、所在地、个人链接 |
| `EducationEntry` | 学校、学位、专业、日期、GPA、课程、证据 |
| `SkillItem` | 名称、分类、熟练度、证据 |
| `ProjectEntry` | 名称、角色、日期、描述、技术栈、亮点、证据 |
| `ExperienceEntry` | 组织、角色、日期、工作亮点、证据 |
| `CertificateEntry` | 证书或荣誉、日期、证据 |
| `CandidateProfile` | 汇总以上结构，并增加求职方向、概述、警告 |
| `ResumeAnalysisResponse` | 文件名、服务商、模型、`profile` |

技能分类限定为编程语言、框架、数据库、工程工具、AI、其他。日期为字符串，保留原始精度。

### 2.4 提示词与结果校验

提示词要求只使用原文信息、不美化补全、单值缺失用 `null`、列表缺失用 `[]`、证据逐字引用、技能熟练度不得推测。

用户提示词携带 `CandidateProfile` 生成的 JSON Schema、最小示例和简历正文。模型返回后通过 `CandidateProfile.model_validate()` 校验。

代码负责 JSON 与结构校验；引用真实性和是否编造经历目前主要依赖提示词，没有逐字原文核验。

### 2.5 页面展示

- 展示实际服务商和模型。
- 按基本信息、求职方向、教育、技能、项目、实践、证书分区。
- 证据区域可展开，`warnings` 单独展示。
- 分析期间禁用按钮并显示加载状态。
- 将结果保留在 `currentCandidateProfile`，供第三阶段复用。

## 4. 数据流与接口

```text
file + provider → /api/resumes/analyze
→ read_uploaded_resume() 再次提取正文
→ build_resume_analyzer(provider) → 读取对应配置
→ ResumeAnalyzer → 提示词、Schema、正文
→ OpenAICompatibleClient → JSON 对象 → Pydantic 校验
→ 返回画像 → 页面展示并保留
```

分析接口接收文件，并不接收第一阶段的正文。所以先解析再生成画像时，会再次上传同一文件并再次提取文本。

| 请求字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | `multipart/form-data` 文件，沿用第一阶段限制 |
| `provider` | 否 | `openai` 或 `deepseek` |

响应字段为 `filename`、`provider`、`model`、`profile`。错误包括文件处理错误、请求参数 `422`、配置错误 `503`、模型调用或结构异常 `502`。

## 7. 当前边界与维护

- JSON 模式和 Pydantic 校验不能保证事实正确，仍应复核结果。
- 没有流式输出、任务队列、长文本切分或自动修复输出。
- API 错误目前主要使用通用提示，未分别解释认证失败、余额不足等。
- 画像默认只在当前页面内存中保留，第四阶段保存时才写入数据库。
- 修改客户端参数需兼顾简历、岗位、匹配三种调用。
- 修改画像字段时同步维护提示词、前端、匹配输入、保存结构、测试、本文件和根目录 README。
