## 2. 具体完成的工作

### 2.1 Python 项目初始化

- 在 `job-agent` 下组织 `app`、`tests` 等代码目录，并建立 `.venv` 虚拟环境。
- 使用 `pyproject.toml` 管理项目依赖、开发依赖、pytest 和 Ruff 配置，以及静态资源打包。
- 使用 FastAPI 创建服务，Uvicorn 启动应用。
- 将 CSS/JavaScript 挂载到 `/static`，通过 `/upload` 提供页面。
- 根目录 `README.md` 作为项目总入口，根目录 `test` 保存人工测试素材。

当前依赖文件已经包含后续阶段添加的 SDK 和数据库驱动，并非全部依赖都属于第一阶段。

### 2.2 三种格式解析

| 格式 | 实现 | 处理细节 |
| --- | --- | --- |
| PDF | PyMuPDF | 从内存字节打开文档，逐页调用 `get_text("text")`，以换行连接 |
| DOCX | python-docx | 提取正文段落与表格单元格，合并为文本 |
| TXT | Python 解码 | 依次尝试 `utf-8-sig`、`gb18030`，兼容 UTF-8 BOM 和常见中文编码 |

`extract_document_text()` 按扩展名选择解析器，对结果清理首尾空白。结果为空时抛出 `EmptyDocumentTextError`，提示扫描版 PDF 需要先进行 OCR。

### 2.3 上传校验与异常处理

- 扩展名转为小写后，仅接受 `.pdf`、`.docx`、`.txt`。
- 后端最多读取 `10 MB + 1` 字节，识别超出限制的文件。
- 空文件、文件过大、不支持格式、损坏文件、无可提取文字分别处理。
- 用 `ParsedResume` 在接口内部传递文件名、格式和正文。
- 提取公共函数 `read_uploaded_resume()`，供第二阶段分析接口复用。

### 2.4 中文上传页面

- 支持点击选择、拖拽上传、重新选择。
- 上传前提示格式和大小问题，显示已选文件名、大小、类型。
- 上传期间禁用解析按钮，展示处理状态。
- 解析成功后展示字符数、格式和完整正文，支持复制。
- 提供错误提示和响应式布局。
- 上传路由调整为 `/upload`，当前根路径 `/` 不提供页面。

## 4. 请求与数据流

```text
选择简历 → 浏览器校验 → multipart/form-data 上传 file
→ read_uploaded_resume() → extract_document_text()
→ 按格式选择 PDF / DOCX / TXT 解析器
→ ResumeParseResponse → 页面显示正文
```

前端校验负责及时提示，后端仍独立校验，直接调用接口也必须满足限制。

## 5. 接口契约

`POST /api/resumes/parse` 使用 `multipart/form-data`，必填字段为 `file`。

| 响应字段 | 类型 | 含义 |
| --- | --- | --- |
| `filename` | 字符串 | 文件名称 |
| `file_type` | 字符串 | 不带点的格式，如 `pdf` |
| `character_count` | 整数 | `len(parsed.text)`，不是字节数或 token 数 |
| `text` | 字符串 | 提取出的正文 |

| 状态码 | 含义 |
| --- | --- |
| `200` | 成功 |
| `400` | 空文件或文档解析失败 |
| `413` | 大小超过 10 MB |
| `415` | 不支持的扩展名 |
| `422` | 无可提取文字，或请求参数不符合约定 |

`/health` 仍存在于 `main.py`；此前删除的是健康检查测试，不是健康检查接口本身。

## 7. 当前边界

- 不支持 OCR、图片简历、旧版 `.doc` 或压缩包。
- PDF 多栏布局不保证提取顺序符合视觉阅读顺序。
- DOCX 当前先收集段落再收集表格，不恢复两者交错的精确顺序。
- 主要按扩展名选择解析器，没有单独的文件内容类型检测服务。
- 本阶段只提取正文；教育、技能、项目等语义信息由第二阶段抽取。
- 文件解析本身不需要模型密钥或数据库，但整合页面现在还会加载第四阶段看板。
